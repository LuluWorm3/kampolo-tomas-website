Design system gallery

The tokens, type, components and accessibility checks behind this site, read live from its own stylesheet, with a contrast checker and a way to re-skin the same markup.

01

The situation

A user interface that grows without shared rules drifts. The same grey turns up in four slightly different values, buttons differ from page to page, and dark mode gets bolted on late and breaks. The usual fix is plain: define colour, type and spacing once as tokens, build every component only from those tokens, and test the result. This site is built that way, from one stylesheet, and this lab reads that stylesheet live in your browser instead of showing a picture of it.

02

What to look at

  1. Switch the theme and watch the contrast table recompute. Every number comes from the colours the browser has just resolved.
  2. Type two colours into the contrast checker. Try #777 on #fff (it fails the small-text target) and then #767676 on #fff (it just passes).
  3. In the last section, apply a different style to this page, then run the check across all eight and see which pairings fall below their target.

        04

        How it is built

        Dependency-free HTML, CSS and one vanilla script, labs/design-system.js. The page loads the site's own /styles.css and reuses its classes, so what you see is the site's real components and not a lookalike.

        • Tokens: found by scanning document.styleSheets for custom properties declared on :root, then read with getComputedStyle, so adding a token to styles.css adds a swatch here. Colours are resolved to sRGB through a 1 by 1 canvas, which accepts any CSS colour syntax.
        • Contrast: the WCAG 2 relative luminance formula. The pass flag uses the exact ratio, never the rounded one.
        • Component specs: each grey line under a component is read from the rendered element, and a value equal to a token is labelled with the token's name.
        • Styles: the plain styles in styles.css are applied by setting data-style on html. This page sets it only in memory. The + editions are separate scripts and are not loaded here.
        • Content security policy: no inline styles or scripts. Dynamic colours are set through the CSS object model.

        Trade-off: the gallery needs a few small rules of its own (labs/design-system.css) for the swatch grid and the checker layout, plus one override so the page's generic heading style does not change the sample .job heading.

        05

        Limits and sources

        • Real: the tokens, classes, computed values and every contrast ratio. They come from this site's stylesheet in your browser at the moment you view it.
        • Sample: the words inside the components are placeholders written for this page. They describe the component and say nothing about any job, project or skill.
        • Scope: the checker implements WCAG 2.x contrast only. It does not check colour-vision differences, text spacing, target size or screen-reader output, and a passing ratio does not make a page accessible.
        • Not tested yet: Firefox, Safari and real phones. Screen readers have not been run against this page.
        • The skill-level bars in the real .skill-list are drawn with CSS only, so their level is not available to a screen reader unless text is added, as the sample here does with hidden text.
